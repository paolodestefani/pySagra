Installazione del programma

Il programma viene fornito con pacchetti di installazione generati di PyInstaller in 2 versioni:

  • Per architettura x86-64 per sistema operativo Windows, compatibile con Windows 10 e versioni successive
  • Per architettura arm-64 per sistema operativo MacOS, compatibile con MacOS 26 Tahoe e versioni successive

E' fornito il programma sorgente quindi è possibile far funzionare pySagra anche su versioni diverse sia del sistema operativo sia dei componenti software rispetto a quanto indicato sopra. Il database server utilizzato è PostgreSQL 18 ma probabilmente il programma funziona anche con versioni precedenti, comunque non testate.

In ogni caso il programma è testato solo con questi componenti e sistemi operativi:

  • PostgreSQL in versione 18.x
  • PySide6 in versione 6.12.x
  • Psycopg in versione 3.3.x
  • python-escpos in versione 3.1
  • Windows in versione 11 pro
  • MacOS in versione 26.x e 27.x

Si si utilizzano i pacchetti generati da PyInstaller per installare il programma è sufficiente copiare la cartella in una qualunque posizione del file systema della macchina da utilizzare. Non servono setup, basta lanciare l'applicativo con le modalità richieste dal sistema operativo:

  • Doppio click sul file pySagra.exe in ambiente Windows
  • Doppio click sulla cartella pySagra.app in ambiente MacOS

Per funzionare l'applicazione ha bisogno di accedere ad un database server PostgreSQL e ad un database applicativo di pySagra. Per l'installazione di PostgreSQL far riferimento ai pachetti di instllazione e alle istruzioni disponibili in www.postgresql.org, il programma può funzionare in ambienti misti con server di database in linux, client in windows o mac o combinazioni di questi ambienti.

Vengono forniti due database applicativi del programma:

  • pyagra è un database praticamente vuoto, contiene solo la struttura del database, gli utenti di base, un'azienda per accedere, report ed altre personalizzazioni
  • pysagra_demo invece contiene oltre a quanto già presente nel db di base precedente due aziende con esempio di configurazioni, anagrafiche articoli, ordini inseriti, ecc.

I database elencati sono in formato backup utilizzabile per il ripristino tramite pg_restore ed in formato sql utilizzabile per il ripristino tramite psql. Quest'ultimo dovrebbe permettere l'installazione anche in versioni precedenti alla 18.x di PostgreSQL. Questi database presuppongono che esistano già due ruoli specifici:

  • pa_owner_role è il ruolo che viene utilizzato come proprietario di tutti gli oggetti del database
  • pa_login_role è il ruolo che viene utilizzato per l'accesso al database, eredita le proprietà di pa_owner_role

All'interno della cartella degli script sql sono disponibili gli script da utilizzare per creare questi ruoli.

E' possibile crearsi un database applicativo da zero utilizzando gli script sql forniti e sostituendo ai parametri seguenti una valore corretto:

Parametro Descrizione Valore
{pyAppPgOwnerRole} PostgresSQL Role that own all db objects without login privilege pa_owner_role
{pyAppPgDataBase} Postgres database name pysagra
{pyAppPgLoginRole} PostgresSQL Role used for standard login users pa_login_role
{pyAppPgLoginPassword} Password for pyAppPgLoginRole *********
{pyAppName} Python application name pySagra
{pyAppDescription} Python application description Food stand management software
{pyAppVersionMajor} Application version major number 1
{pyAppVersionMinor} Application version minor number 0
{pyAppVersionPatch} Application version patch number 0
{pyAppVersionTag} Application version tag A new world
{pyAppVersionDescription} Application version description
{pyAppPgDataBaseTS} Database table space (MUST be created before script execution) pg_default
{pyAppPgTablesTS} Tables table space (MUST be created before script execution) pg_default
{pyAppPgIndexesTS} Indexes table space (MUST be created before script execution) pg_default

Nella colonna Valore sono riportati i valori per la versione di pySagra 1.0.0. Non tutti i parametri vengono utilizzati su tutti gli script.

La versione del programma e del database devono coincidere nei rispettivi numeri major e minor. Ad esempio se il programma è in versione 1.0.23 funzionerà con database in versione 1.0.x dove x può assumere qualunque valore.
