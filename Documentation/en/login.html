Login procedure

To use pySagra it is necessary to connect the program to a PostgreSQL database server where a pySagra application database is already present. Please see the specific instructions for installing the server and the application database.

At the first launch of the application, the connection parameters to the server are requested and the window appears as shown in the figure:

The parameters required to connect to the database server are:

  • User: enter the application user code. The entered text is case-sensitive, meaning "Paolo" and "paolo" are interpreted as 2 different users.
  • Password: enter the password associated with the selected user. It may be optional depending on how the user authentication mechanism is configured.
  • Server: enter the name of the computer acting as the database server. It is also possible to enter the server's IP address (e.g., 192.168.1.1). If the program is running on the same computer where the database server is running, you can enter the computer name 'localhost' or the IP 127.0.0.1
  • Port: indicate the TCP port to use for the connection. Typically, PostgreSQL installations use port 5432; ask your network administrator if a different port is used
  • Database: indicate the name of the database to connect to
  • DB User: indicate the name of the database user to log in to the database server and access the application database. This is a PostgreSQL server user and has nothing to do with the application user requested above.
  • DB Password: indicate the password of the database user specified above.

Using the Clear local settings button, it is possible to reset any application settings stored locally on the PC (not in the database) that have caused problems. Typical examples include: accidentally hiding all toolbars, changing the window size making it invisible, etc.

There are 2 default and non-modifiable system application users:

  • system with password system
  • sistema with password sistema

These users are administrators and are assigned a menu and a profile that allows them full access to all program features. It is recommended to change their password upon first access, but it is not mandatory

Additionally, 2 other users are preloaded:

  • user with password user
  • utente with password utente

Since they are normal users, they can be modified and even deleted. They are restricted in various ways, but any administrator can modify their permissions, profiles, and menus
