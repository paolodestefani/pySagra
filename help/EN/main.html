Overview

One of the traditional and cultural characteristics across Italy is the presence of Sagre (local festivals). As clarified by Wikipedia, a sagra is a popular local festival held annually. It traditionally originates from a religious celebration, held on the occasion of a consecration or to commemorate a saint (usually the patron saint), but it is also used to celebrate the harvest or to promote a local food and wine product. During a sagra, a local fair, a market, and various celebrations usually take place. The most important area of the festival, at least from a culinary perspective, is the food stand. pySagra was born from the need to manage the food stand of my hometown's festival. The management workflow starts from taking product orders, typically first courses, second courses, drinks, etc., and the subsequent distribution of order tickets, which act as actual production orders, to the various departments of the stand, such as the bar, the kitchen, as well as the pizzeria, ice cream station, etc. Order entry takes place at the cash desks and must be as fast and simple as possible. Once entered, the order is divided by department and routed to the relevant stations. Managing order fulfillment and product stock is usually unnecessary for this type of activity, which prioritizes the speed of order handling and food delivery. At the end of the day or at the conclusion of the festival, results are verified through a revenue summary and various sales and consumption statistics.

The program allows managing all these aspects, from order loading to product delivery and final statistics.

The features of the application can be summarized in the following points:

  • Event management: all operations are always referenced to a specific event (e.g., Pepper Festival, Beer Festival, etc.).
  • Department management (e.g., Bar, Kitchen, Pizzeria, etc.). Some departments may be unavailable for specific events.
  • Management of sales and consumption items, distinguishing them into basic items, kits - composite items (e.g., trio platter: sausages + ribs + pork chop) and menus - groupings of items from various departments (e.g., festival menu: beer + trio platter + french fries). Kits must consist only of basic items. Menus can contain kits.
  • Management of item variants (e.g., pizza margherita without mozzarella, with spicy salami, etc.). The variant can include a price surcharge.
  • Management of dine-in (table) or takeout delivery.
  • Stock control: for basic items that need monitoring, it is possible to input the available stock. The program automatically updates the availability based on sales made and subsequent consumption.
  • Ordered - Delivered control: for items that need monitoring, it is possible to track the committed quantity and the subsequent delivery, also managing order fulfillment. The program automatically updates the order status (entered, processing, fulfilled) based on the deliveries made.
  • Sales order management via a loading screen optimized and designed to achieve the maximum entry speed. Check for the existence of the indicated table. Possibility to select the table from an interactive layout map of existing tables. Check for the availability of the entered items, considering the components for kits and menus. Automatic calculation of order total, amount received, any value discounts (e.g., vouchers), change due, etc. Display of possible variants.
  • Possibility to insert notes per department
  • Orders can also be entered in a web application that generates a QR Code that can be scanned at the cash desk for quick acquisition, followed only by payment.
  • Generation of the order printout for the customer, specific printouts for the various departments involved, and one for table covers only. All these printouts are optional and available in various formats
  • Printout of revenue by day and half-day
  • Continuous display and printing of item availability or the components of kits and menus.
  • Management of various sales and consumption statistics, including comparing different events and periods
  • All records (events, departments, items, etc.) and available statistics can be viewed, printed in A4 format, and exported to CSV/Excel
  • The application is cross-platform: developed and tested on Mac OSX and Windows, it should also function correctly on Linux.

Application Architecture

This program was developed with some specific goals in mind:

  • Create an application with a graphical interface based on an SQL database server
  • Create a multi-user application with a client/server architecture
  • The application must be cross-platform and available at low or no cost to anyone who requests it

To build this application based on the previous premises, the following tools were chosen:

  • the Python programming language in version 3.14
  • the Qt libraries in version 6.x
  • the binding to the Qt libraries Qt for Python in version 6.x
  • The PostgreSQL database server in version 18.x or later
  • The PostgreSQL connector for Python Psycopg in version 3.3.x or later
  • the default icon set is oxygen but other icon packs downloaded from Iconarchive are also available
  • the pySagra icon is part of the DelliOS System Icons set by dellustrations.com

All the listed tools are cross-platform and available free of charge
